# 实体试钩记录与校准

**简体中文** | [English](physical-trials.en.md) | [文档索引 / Documentation index](README.md)

试钩工具把“尺寸可能需要调整”变成可追溯数据，但不会自动修改生成器常数。
原始记录与报告默认放在 Git 忽略的 `trial_data/`、`trial_outputs/`。

试钩不要求由项目作者本人完成：第三方可按本系统导出的精确图解实施，并提交
图解哈希、小样、实际尺寸/用线、分口径工时及匿名制作者等完整记录。记录按相同
协议核验，校准集与验证集仍须隔离。网上教程或相似成品介绍只能作规则/数量级
参考；当前 `external_evidence` 摘要不会自动升级为合格试钩。原始资料与适用范围
见[网络方法能验证什么](SOURCES.md)。

## 1. 从精确图解创建草稿

### 在网页中记录与恢复

结果页展开「🧪 实体试钩记录」，填写试钩编号、稳定的匿名制作者编号和记录用途，
点击「以当前图解新建试钩」。系统保存当时的完整图解；这份原图解在后续填写过程中保持不变。

1. 先记录实测小样密度、钩针与线材，点击「保存记录并更新下载」，下载草稿 ZIP。
   初始小样密度来自图解，须换成实测值后才能勾选「已实际测量小样」。
2. 尺寸、用线、工时和备注都可分次填写，未测的数据留空，先保存草稿。全部完成后勾选
   「标记为完成（需填写必填测量）」，填写完成日期、总高、用线克数和实际操作分钟数。
   工时默认包含装配收尾；只有计时确实仅涵盖逐圈钩织与换圈时才选择对应口径。
   改过图解须勾选并逐行说明。保存后显示实测总高相对原目标的偏差。
3. 下载更新后的 ZIP。下载内容只包含上次成功保存的数据；输入未保存或校验失败时，
   原记录和原下载仍保留。切回草稿后保存会保留已填写的测量，之后可继续补齐。
   表单字段始终显示，切换完成状态不会清空输入；完成日期留空时不会自动填成当天。
4. 下次从侧栏「🧪 打开试钩包」上传 ZIP，点击「打开试钩及原图解」，无需先生成图解。
   原图解和实测记录会恢复到照片页，替换该页当前图解和试钩记录；手动输入页不受影响。
   结果页内的「恢复试钩记录」只替换该面板记录，不改变当前图解。

同一会话调整图解不会重新绑定已有试钩；界面会提示差异，记录仍对应原图解。
如果实物也采用修改，应在完成记录中声明；新设计应先下载旧记录，再结束并新建试钩。
每个结果页同时编辑一份试钩记录，照片页与手动页独立。

### 撤销或重做已保存记录

保存后可点击「↶ 撤销保存」或「↷ 重做保存」，恢复小样、线材、测量及草稿/完成状态。
表单、实测对照和下载内容一起切换，不改变当前图解、钩织进度或工程备注。
表单有未保存修改或无效值时，撤销/重做会停止并保留输入；请先保存，或将输入改回已保存值。
撤销后保存不同内容会清空重做分支；重复保存相同内容不新增历史，也不清空重做。

历史仅保留在当前会话，撤销和重做合计最多 8 份、2 MiB，超限移除较早保留的记录；
原图解只保留一份。重新打开试钩包或结束记录会清空历史，ZIP 也不保存历史。
需要长期保留某个版本时，请切换到该版本后下载。

### 试钩包格式与保存范围

试钩包包含 `pattern.json` 和 `<试钩编号>.trial.json`，沿用试钩模式版本 2。
保存未完成测量时另有可选的 `draft.json`，使用独立版本 1，见
[草稿 JSON Schema](schemas/trial_draft_state.schema.json)。它通过 `record_sha256` 绑定
同包试钩 JSON 的确切字节，试钩记录再绑定原图解；三者不可从不同下载中混合拼装。
草稿允许缺少测量，但已填写的数值、日期及文字仍须满足范围和长度限制。
原图解按确切文件字节计算 SHA-256，恢复时核对哈希以及目标高度、密度、实体针数/圈数和
预计工时。图解限 20 MiB，试钩 JSON 与可选草稿各限 512 KiB；ZIP 在内存中按成员限量读取，
不解压到磁盘。损坏、重复成员、未定义的额外文件、路径成员、非有限数值或不匹配的记录包
会被拒绝，当前工作不变。

未完成测量只属于草稿：正式 `*.trial.json` 保持 `status="draft"`、`observation=null`，
不会进入成品偏差或校准统计。标记完成并成功保存后，数据通过现有完成记录校验再进入
正式 `observation`，ZIP 不再包含 `draft.json`；取消完成并保存会把测量放回草稿而非删除。
只有小样/线材、没有未完成成品测量时，仍使用原来的双文件 ZIP。新版兼容旧包；含草稿的
三文件包需要新版应用恢复，旧版 CLI 仍可读取其中的正式记录并忽略草稿状态的样本。

试钩包不包含钩织进度、工程备注或撤销历史；试钩记录也不进入普通图解备份、工程文件或分享链接。
需要同时保留钩织进度时，另存「我的钩织工程」。试钩包中的匿名编号、线材和测量备注随文件下载，
关闭会话前请保存。恢复不代表实测内容已被独立审核，也不会自动修改生成器常数。

### 实测对照与密度重算

试钩面板中的对照表只读取上次成功保存的记录，显示针/行密度、成品总高、用线和工时。
差异按「实测 ÷ 原图解值 − 1」计算。未确认实测的小样不显示为测量值；旧图解缺少用线
估算时显示「未记录」。完整项目工时与原基础工时标明口径不同，不计算百分比。
改过图解的记录仍可观察差异，但差异也包含改图影响，不能直接归因于生成器。

已保存实测小样的草稿和完成记录都可用于密度重算：

1. 填写实测针数和行数，勾选「已实际测量小样」，点击「保存记录并更新下载」。
2. 当前图解须与试钩原图解一致，且实测密度有所变化。若图解已被修改，可从侧栏打开
   原试钩包；这个入口不会把旧测量应用到另一份设计。
3. 点击「预览按实测密度重算」，到下方「局部修正」查看密度、总针数、材料估算和进度影响，
   再选择「应用这次修改」或「取消预览」。输入或记录再次改变后应重新预览。
4. 应用后保存更新图解；如需针对新图解试钩，下载旧记录后结束它，再建立新的试钩。

重算保留目标尺寸、结构、配色生成输入、线材规格及固定腰位比例，重新生成针数、圈数与
实际接合引用；逐圈手改会被生成结果替换。密度改变后所有已完成圈次需重新核对，个人备注
保留，撤销可恢复旧密度、图解与进度。密度相同不触发重算，也不覆盖手改内容。
原试钩记录和下载包保持不变，不会改成新图解的测量证据。这里使用小样密度重新生成，
不根据一次成品高度偏差反推缩放系数，也不修改全局用线或工时常数；仍需后续试钩确认效果。

### 使用命令行创建与汇总

网页试钩包解压后的 `*.trial.json` 可直接放入 `trial_data/`，使用下方 `analyze` 命令汇总；
请保留同包的 `pattern.json` 原始字节以便复核。含 `draft.json` 时，试钩 JSON 的原始字节
也用于校验，请通过网页补齐并保存，勿直接改写或重新格式化包内文件。草稿不会成为完成样本。
也可按原命令行流程创建记录：

先生成完整图解 JSON，再创建绑定其 SHA-256 的试钩记录：

```bash
uv run crochet2pattern --mock --out pattern.json --quiet
mkdir -p trial_data trial_outputs
uv run crochet2pattern-trials init \
  --pattern pattern.json \
  --trial-id classic-001 \
  --maker-id maker-a \
  --cohort calibration \
  --out trial_data/classic-001.trial.json
```

`maker_id` 应使用稳定的匿名标识，不要填写姓名、邮箱或账号。工具会从图解正文
重新计算实体总针数和总圈数，不信任可能过期的派生字段。

## 2. 完成记录

钩织完成后编辑 `*.trial.json`：

```json
{
  "status": "completed",
  "swatch": {
    "measured": true,
    "stitches_per_10cm": 13,
    "rows_per_10cm": 16,
    "hook_mm": 4,
    "yarn_brand": "品牌",
    "yarn_line": "系列",
    "yarn_lot": "批次",
    "fiber": "棉"
  },
  "observation": {
    "completed_on": "2026-08-30",
    "overall_height_cm": 18.7,
    "yarn_used_grams": 92.4,
    "yarn_used_meters": null,
    "active_minutes": 162,
    "time_scope": "round_crochet_baseline",
    "pattern_modified": false,
    "modifications": [],
    "notes": "仅记录与复现相关的信息"
  }
}
```

实际文件还必须保留 `schema_version`、`trial_id`、`maker_id`、`cohort` 和工具生成的
`pattern` 字段。建议：

当前试钩模式版本为 2。旧的版本 1 完成记录需要补上 `time_scope` 并将
`schema_version` 改为 `2`；工具不会猜测旧记录是否包含收尾工时。早期版本2记录没有
`cohort` 时会兼容为 `calibration`，但留出验证记录必须显式写
`cohort="validation"`。

- `active_minutes` 只计实际操作时间，暂停和等待不计入。若只计逐圈钩织和换圈操作，
  使用 `time_scope="round_crochet_baseline"`；若包含缝合、填充、换色、刺绣或其他收尾，
  必须使用 `time_scope="full_project"`，该工时仍会显示但不会推导每针秒数。
- `yarn_used_grams` 只计毛线，不含填充棉、安全眼、金属件和剩余线团。
- 只有可靠测量起始/剩余长度时才填 `yarn_used_meters`。
- 任何增删圈、改针数或改部件都必须设置 `pattern_modified=true` 并写入
  `modifications`；这类记录仍参与偏差观察，但不进入常数校准。

## 3. 聚合分析

```bash
uv run crochet2pattern-trials analyze \
  --records trial_data \
  --out trial_outputs/baseline.json
```

- `0`：克重与基础工时两组都至少有5个完成且未改图解的合格试钩，并各自覆盖至少3个
  已升级的不同设计指纹和2名匿名制作者，可以进入人工校准审核。
- `1`：记录格式、范围、重复 ID 或 JSON 无效。
- `2`：报告已生成，但样本数量、多样性或设计身份验证不足。

探索期可添加 `--allow-insufficient`，但报告仍保持
`summary.calibration_ready=false`。

### 独立留出验证

候选常数只能来自 `calibration`。至少另外准备3个完成、未改图解、基础工时口径的
`validation` 记录，覆盖至少2个不同设计指纹和2名匿名制作者，而且这些设计不得出现
在校准集中：

```bash
uv run crochet2pattern-trials init \
  --pattern unseen-pattern.json \
  --trial-id holdout-001 \
  --maker-id maker-b \
  --cohort validation \
  --out trial_data/holdout-001.trial.json

uv run crochet2pattern-trials analyze \
  --records trial_data \
  --require-validation \
  --out trial_outputs/release-review.json
```

`--require-validation` 会在留出样本不足、设计身份未升级或队列重叠时返回2。
当前 `pattern.design_fingerprint_version="1"` 使用规范化密度与各实体的逐圈针数、
加减针序列；忽略部件排列、名称、配色、诊断与相同实体的等价分组。圈序与总数量保留，
因此仅重排、重命名或把一对部件拆成两条记录不会增加设计数。这是保守的针数结构去重，
不能证明完整工艺或实物等价；计数相同的不同工艺可能合并计数。跨队列同时检查原图解
SHA，不能因新旧身份字段不同而漏掉同一文件。
报告中的 `independent_validation.sample_ready=true` 只证明样本量、设计多样性和
队列隔离满足，不会自动宣称当前或候选常数准确；仍需人工审查尺寸、克重和工时偏差分布。

### 升级旧试钩记录

旧记录没有指纹或只有无版本指纹时，仍可读取并展示测量分布；在升级前不计为已确认的
独立设计，也不会据此给出可校准候选。报告列出 `summary.unverified_design_records`；
`independent_validation.design_identity_complete=false` 时，
`cohort_pattern_hashes_disjoint=false` 表示尚不能确认独立，不一定已有具体重叠。

网页重新打开原试钩 ZIP 时，先核对确切图解字节 SHA、旧元数据、旧指纹（若有），
以及未完成测量草稿与原记录的绑定，再升级身份。原图解字节、制作者、小样、完成记录
及未完成测量保留；重新下载时草稿绑定新的记录字节。两文件和三文件旧包均可恢复。

只有独立 `.trial.json` 文件时，可用同一次保存的原图解升级，不必重填测量：

```bash
uv run crochet2pattern-trials migrate \
  --pattern original-pattern.json \
  --record trial_data/old.trial.json \
  --out trial_data_upgraded/old.trial.json
```

原图解即使只重新排版也会改变字节 SHA，不能用于迁移。输出默认不得覆盖已有文件；
`--force` 只允许替换旧输出，不能覆盖原图解或输入记录，包括指向输入的别名。
失败保留原输入和已有输出。汇总时请选择升级后的目录，不要同时加载同一 `trial_id`
的升级前后记录。根试钩模式仍为 2，报告模式仍为 3，新增可选的指纹算法版本字段。

## 4. 报告口径

- 尺寸：实际总高 ÷ 图解目标总高。
- 密度：实际小样针/行密度 ÷ 图解密度。
- 克重：实际克数 ÷ 实体总针数，再按针宽×行高归一到默认基准针面积。
- 工时：从实际秒数扣除当前每圈10秒固定开销，再除以实体总针数。
- 米数：仅使用同时记录实际米数和克数的案例，换算到每100g。

聚合值使用中位数并同时报告中位绝对偏差、最小值和最大值，降低个别异常样本
的影响。即使数量达标，归一化克重或单针工时的相对中位绝对偏差超过25%，也不会
产生相应候选值。克重与基础工时有各自的 `ready` 和 `blockers`；完整项目工时不会
阻塞克重候选，但不能产生每针秒数候选。`init` 默认拒绝覆盖已有记录；只有明确传入
`--force` 才允许覆盖。
候选值出现也不代表应立即修改生产常数；正确流程是人工检查原始案例、修改常数、
用未参与校准的独立试钩集再次验证。

该工具暂不建模个人钩织速度、不同针法、填充松紧、纤维吸湿和线批差异。
样本增加后应按制作者、线材/针号和图解复杂度分层，而不是把所有记录混成一个常数。

## 5. 网络试钩证据

发行包内置一个只保存少量事实、来源与使用边界的
[`external-trial-evidence.json`](../app/data/external-trial-evidence.json)。它不包含外部图解正文、
图片、用户名或自由文本项目笔记。先单独验证并生成上下文报告：

```bash
uv run crochet2pattern-trials external-report \
  --curated \
  --out trial_outputs/external-context.json
```

也可以把该上下文附在本地试钩报告中：

```bash
uv run crochet2pattern-trials analyze \
  --records trial_data \
  --curated-external-evidence \
  --out trial_outputs/baseline-with-context.json
```

如需使用自有证据文件，把 `external-report --curated` 换成
`external-report --evidence path/to/evidence.json`，或在 `analyze` 中使用
`--external-evidence path/to/evidence.json`。内置和自有证据参数互斥，防止来源混淆。

外部证据模型强制记录来源 URL、访问日期、证据类型、验证层级、原始记录是否可得、
复用依据和样本声明。`calibration_allowed` 在模式中固定为 `false`；外部数字只能出现在
`external_evidence` 上下文，不能改变 `recommendations` 候选值。

当前索引有三种不同证据强度：

- Ma Pelote 声称其工时汇总来自 312 个完成项目和平台计时器，并公布了尺寸、工时中位数
  与部分范围；但原始逐条记录不可下载，当前验证层级仍是 `source_claim`。
- 作者完成样品可以提供用线、尺寸或时间，但通常没有本系统所需的精确总针数和图解哈希。
- “约需多少线”的图解规格即使配有成品照片，也不能等同于称重后的实际消耗，因此单独标为
  `published_pattern_specification`。

基于这些限制，网络数据目前只适合两件事：检查系统估算是否存在明显数量级偏差，以及确定
后续本地试钩应优先覆盖哪些尺寸。不能用“同样高 18 cm”直接推导每针秒数，因为部件数、
缝合、换色、刺绣、针法、线材和制作者熟练度都可能不同。

调研时还检查了两个看似相关但未收入证据文件的来源：CrochetBench 是图解理解/生成基准，
不是实体试钩记录，而且数据集采用限制商业用途的 CC BY-NC 4.0；Ravelry 条款也不支持把
站内图解或用户内容默认批量复制到本项目。未来若接入 Ravelry，应仅接受用户授权导出的
自有项目数据，并继续保留来源和权限信息。
