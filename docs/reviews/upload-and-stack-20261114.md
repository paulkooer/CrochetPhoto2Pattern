## 确定性竞态与修复

旧请求进入队列 → 客户端提交目标文件 → 旧请求才开始并成功结束 → 目标运行尚未开始。
新事件测试先在原 #88 实现上失败，实际得到 `older-queued-run`，复现审核指出的假阳性。

修复要求目标请求之后的完整运行，收到同运行 ID、目标文件 ID、目标内容 SHA-256 的服务端确认，
且确认严格位于该运行的开始/成功结束之间。测试入口在 `file_uploader` 返回文件时读取其完整
缓冲区并发送确认；客户端对上传的同一字节快照求哈希，路径输入先冻结为缓冲区。
这证明该运行已取得目标字节；它不替代图片/JSON/ZIP 解析及实际下载的业务断言。

适配器仅由隔离测试服务 `scripts/browser/serve_app.py` 安装，不修改生产应用。
依赖 Streamlit 内部运行描述符与控件接口，升级框架须重新验证。
页面/连接关闭及解码失败仍使本页观察器失败；本轮不声称实现重连恢复或通用并发上传。

真实浏览器通过 WebSocket 门闩暂存两个请求：只放行旧请求，确认它成功结束而 helper 保持等待；
再放行目标请求，立即读取目标内容末尾标记。这项测试在删除内容确认后仍会通过，
只能证明请求/运行等待，不能作为内容确认的浏览器证据。

根据 Fable 的故障注入探针，新增浏览器用例让服务端除上传地址回复外的消息延迟 1 秒，
先点击旧请求再上传，连续 5 轮确认目标请求先于旧运行开始消息进入观察日志；
helper 返回后立即读取目标内容标记。这是人为控制消息到达顺序，不声称自然连接中已复现。
删除内容确认现在必须被这条真实浏览器断言拒绝，纯协议变异也继续保留。
单元测试覆盖错误哈希、文件/运行 ID、运行边界、中断、片段运行及缺少目标文件 ID 的请求。
真实片段结束状态改为 `3`；状态 `0` 的片段测试保留为明确标注的冗余防线变异。
非 JSON 的无关 parent 消息不再永久破坏观察器，本协议的畸形确认仍使其失败。

隔离服务入口把自身仓库根目录插入 `sys.path` 最前面，新增无 `.venv`、借用主检出环境且从其他
目录启动的来源回归。上传确认携带实际 `app.__file__`，完整报告记录 `server_app_file`，
并要求它与报告对应检出的 `app/__init__.py` 一致。
