## 1. 系统一句话定位

照片 → Amigurumi（立体钩织玩偶）图解生成器。双路径：AI 视觉解析
（OpenAI/Anthropic 严格结构化输出 + 中转站）与本地免费管线（人脸检测 +
GrabCut 主体分割 + Otsu 种子 + 可选姿态关键点实测 span）。输出：逐圈
X/V/A 符号图解（三密度×球型×一体×裙型全组合，264 组参数矩阵门禁 +
hypothesis 不变量）、逐圈配色与换线、逐色材料（克重/米数/品牌色号）、
自检徽章、环形图+符号条、轮廓验证 SVG、JSON 局部修正、快速调尺寸、
进度勾选、Markdown/PDF 导出、SQLite 历史、分享链接、CLI 无头模式。
Streamlit GUI + CLI 双形态，Python 3.9+，本地优先。

## 4. 已知局限（可作为优化切入点的背景）

1. 单图信息极限：背面厚度靠常识；本地模式头径锚 9cm
2. pose 不可用时部件分段回退 PART_SPAN 先验
3. 旋转体假设：剖面身体=宽度剖面×圆截面，非圆截面不准
4. tab_photo 上传交互无 AppTest 覆盖（框架限制）
5. 分享链接 >6000 字符被拒（大图解只能文件分享）
6. 历史无搜索/标签/跨设备
7. PDF 无分页优化（长部件表格跨页由 reportlab 自动处理，无精排）
8. 403 行的 image_parser.py 与 881 行的 crochet_params.py 是两个巨型
   模块（拆分时机可议）

## 5. 建议探索的优化维度（引导性问题，非穷尽）

**正确性/健壮性**
- 门禁矩阵 264 组之外还有哪些组合面？（例如 spans+one_piece+egg 的
  桥接交互、ruffle_hem 的装饰性跳变是否需要 validator 白名单）
- hypothesis 只覆盖了生成器主路径——color_bands/validator/subject
  种子是否也值得属性化？
- 异常脱敏是否有漏网入口（history blob、share token、PDF 元数据）？

**产品/用户**
- 钩织者的真实工作流还有什么未覆盖？（试钩小样记录、尺寸拟合反馈
  回流、多种毛线材质提示……）
- 分享链接体验：接收方打开后能否"另存到我的历史"？
- 历史列表搜索/标签/按色筛选？

**性能/资源**
- 全管线 0.5–0.7s（1200px 图）——哪里值得再快？（GrabCut 5 次迭代、
  CIEDE2000 全像素分配是热点？量过吗？）
- 572 测试 ~16s——CI 时长是否需要分层（smoke/全量）？

**生态/工程**
- CLI 之后：批量目录模式？评测基线能否吃真实图片集？
- Python 3.9 还能撑多久（EOL 2025-10）？升 3.10+ 的兼容面？
- crochet_params.py（881 行）拆分方案？

**生态集成**（先核实再建议）
- Ravelry/社交平台导出格式
- SVG 符号图对齐 Craft Yarn Council 标准（对照 CrochetPARADE）
