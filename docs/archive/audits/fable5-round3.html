§1实锤问题（经实验复核）

F1 · 裙子是闭口杯形，套不进腰部 高 · 领域正确性

app/models/crochet_params.py:310-325 · _cup_rounds() · docs/handoff-review.md §2

证据（实测）：生成含裙子的图解，裙子 R1 = 魔法环起6针（X×6），逐圈加针到 48 针后直钩。魔法环起针意味着腰部一端是闭死的圆盘——只有裙摆开口。部件说明却写"开口裙筒……套在腰部后缝合固定"：闭口端无法让身体穿过，物理上套不进去。这与已修复的"帽子闭口球戴不进去"是同一族缺陷——帽子（顶部理应闭合）修对了，裙子（两端都应开口）复用 _cup_rounds 时把闭口端带了进来。

连带不一致：structure_designer.py:32 把裙子映射为 cylinder，参数层却生成 cup——UI 第 2 节向用户展示的形状与第 3 节图解自相矛盾。交接文档 §2 "裙子=开口裙筒" 亦与代码不符（按文档自己的约定指出失实处）。

假信心：test_skirt_is_open_and_wider_than_body 只断言"末圈无收针"（裙摆开口），没断言起针端开口，因此闭腰逃过了测试。

建议修法
  • 裙子改为环形开口起针：以腰围针数（≈身体针数 36）锁针环起 → 1–2 圈内加到裙摆针数（48）→ 直钩至裙长；magic_ring=False。
  • structure 层为裙子引入独立形状名（如 tube/skirt），两层口径统一。
  • 补方向性测试：断言裙子 R1 针数 ≈ 腰围而非 6。

F2 · 身体/手臂/腿部的照片配色方向颠倒 高 · 领域正确性

app/models/crochet_params.py:350-372 · _apply_color_plan()

证据（实测）：喂入色带「上=肤色，中=红（上衣），下=蓝（裤），底=黑（鞋）」，腿部逐圈色序为 [蓝×5, 黑×2]——鞋色被铺在最后两圈。但按代码自身的装配语义，腿从脚底魔法环起针，末圈"断线留15cm用于缝合"到身体底部：R1 = 脚底，鞋色应在 R1–R2。现在的图解会让人把鞋色钩在腿根。

根因：_apply_color_plan 对所有部件统一按「R1 = 部件纵向区间顶端」映射（frac = span_s + span_len·(j+0.5)/n）。这对从顶端起针的部件（头部、帽子）正确；对末圈为缝合端的部件（身体：末圈收针后缝头部；手臂：末圈缝肩部；腿部：末圈缝身体底）——起针端在空间下方，映射整体颠倒。身体单色场景（占比区间恰与一条色带重合）掩盖了该问题，双色裤袜/鞋类照片必现。

建议修法
  • 为每个部件声明钩织方向（_BOTTOM_UP = {"身体","手臂","腿部"}），对这些部件用 frac = span_e − span_len·(j+0.5)/n。尾巴方向存疑（水平部件），可保持现状并注释。
  • 补方向性测试：底部色带的颜色必须出现在四肢的 R1 端。

F3 · 圆柱"标注高度"把起底圆盘计入高度，实测偏大 ~68% 中高 · 领域正确性

app/models/crochet_params.py:294-341 · 身体/四肢分支 · docs/handoff-review.md §2 末条

证据（实测）：结构层要求身体高 4.5cm，生成的标注高度为 9.4cm（15 圈 ÷ 1.6 圈/cm）。但加针段 6 圈是水平的起底圆盘——贡献直径、几乎不贡献高度；物理高度 ≈ (7 圈直钩 + 2 圈收针) ÷ 1.6 ≈ 5.6cm。"标注 = 实际钩出"这一口径隐含"每一圈贡献 1/1.6cm 高度"的假设，对圆盘段不成立。四肢同理（1.2 圈/cm）。

连带影响：用户输入总高 18cm 时，头 9cm + 身体标注 9.4cm 已超总高，加四肢后图解各处高度自相矛盾；test_annotated_height_matches_round_count 锁定的正是这一错误口径——测试断言了实现而非领域事实。

建议修法
  • 标注高度改为 (直钩圈数 + 收针圈数) ÷ 密度（圆盘段只计直径），或按球冠近似给圆盘一个小的高度贡献。
  • 同步更新 test_annotated_height_matches_round_count 的口径与注释，并请按你们的流程试钩一个 24 针小圆柱实测校准。

F4 · 背景色估计：注释称"众数"，实现是量化后均值 中

app/models/color_design.py:40-52 · app/models/local_vision.py:77-82（重复实现）

(samples // 16 * 16).mean(axis=0) 不是众数：量化后取均值只引入每通道约 −7.5 的系统性偏暗，并无抗噪作用。更实质的风险：双色背景（白墙 + 深色地板是人像常见构图）时均值落在两色之间，与两种背景像素的距离都可能超过阈值 48，背景剔除退化为"全图皆主体"，直接拉低配色带与轮廓剖面（裙摆检测）的质量——这两条正是 §5.2/§5.3 请求外部意见的链路。另外该逻辑在两个文件里各写了一份（_BG_DIST_THRESHOLD 也定义了两次）。

建议修法
  • 改为真众数（量化后 np.unique(axis=0, return_counts=True) 取最大计数），或至少逐通道中位数。
  • 抽出共享的 estimate_background(px) 到一处（如 colors.py 或新 util），两处引用，注释与实现对齐。

F5 · JSON 修正后装配说明不重算 低中 · D13 盲区

app/models/crochet_params.py:192-204 · refresh_derived()

用户在 JSON 编辑器删掉帽子部件后，时长/总针数/材料都会重算（D13），但 assembly_instructions 原样保留——装配说明仍写"帽口不收口，直接戴在头部"。装配步骤生成逻辑已在 _build_result 中按部件条件化，抽出后在 refresh_derived 里复用即可（用户手改过 assembly 的场景可用"仅当 parts 集合变化时重算"折中）。
