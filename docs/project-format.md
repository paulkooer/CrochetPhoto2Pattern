# 钩织工程与预留半针接合

本说明对应 2026-10-26 的实现。图解备份、工程状态和针目连接各自独立版本化；
两项新增结构的 JSON Schema 见 [project_state](schemas/project_state.schema.json) 和
[loop_attachment_plan](schemas/loop_attachment_plan.schema.json)。

## 保存工程

结果页展开「我的钩织工程」，填写备注，再点击「保存工程（含进度）」。
弹窗中的 JSON 是点击保存时的快照，包含当时每份部件已完成的圈次。继续工作后须再次保存。
关闭页面前将文件下载到自己的设备；从侧栏「打开备份图解」上传，即可在照片页继续。
结果页自身的导入入口则恢复到所在标签页。

普通「备份完整结果」及分享链接只携带图解；私人备注和进度只进入工程文件。
撤销/重做历史仍属于当前会话，不随工程保存。旧版应用可能只读取工程的图解部分，
请用支持工程状态的当前版本恢复进度。

工程保留现有顶层 `schema_version="1"`、`analysis`、`structure`、`params` 等图解字段，
增加可选的 `project_state`：

```json
{
  "schema_version": "1",
  "pattern_revision": "图解规范序列化后的 64 位 SHA-256 十六进制值",
  "saved_with_version": "保存文件的软件版本",
  "completed_rounds": {
    "[\"手臂\", \"arm_left\", 3]": true,
    "[\"手臂\", \"arm_right\", 1]": true
  },
  "notes": "个人线材、暂停位置或返工备注"
}
```

上例展示 `project_state` 的形状，哈希占位文字不是可导入值。圈次键由部件名、
结构中稳定的实体 ID 和实际圈号组成；旧结构使用 `copy1`、`copy2` 等实体序号。
只有已完成圈次写入 `true`，未完成圈次省略。备注最多 20,000 个字符。
文件上限 20 MiB，粘贴上限 2 MiB；带 BOM 的 UTF-8 文件可读取。

图解修订值来自 `PatternResult.to_backup()` 的 UTF-8 JSON：键排序、无多余空白、
保留 Unicode 字符、禁止非有限数值，再计算 SHA-256。会话 ID、个人备注和进度不参与哈希。
导入先校验图解、工程版本、哈希绑定及圈次身份，再一次性替换目标图解和进度。
工程被手动改动导致图解与进度版本不符时拒绝导入，保留当前工作；应在应用内修改后重新保存。

编辑图解时，未变化部件及仍存在的实体保留进度；发生变化的部件清除其已完成圈次。
密度变化清除全部进度；接合位置改变或身体改变也会清除依赖它的接裙进度。
界面报告清除的圈次数，撤销可恢复；个人备注跨修改及撤销保留。
此策略按部件保守清除，不自动判断已钩织的前缀是否仍能用于修改后的实物。
预留针目连接的影响会逐层传递；例如外层接中层、中层接内层、内层接基底，修改基底时
三层进度都会清除，与连接记录的排列顺序无关。修改外层不会清除未改动的基底。

长图解分页界面显示所选部件的第一个未完成实体和圈号，点击「前往下一未完成圈」
可跳到对应页；选择逻辑按实体序号、图解圈序查找，并非按最近点击的时间猜测。
跳转不修改勾选状态；全部完成时按钮禁用，重置后可返回第一圈。

## 接裙工艺

新生成的挑针接裙图解在 `params.stitch_attachments` 中记录：

```json
{
  "schema_version": "1",
  "connections": [{
    "source_part": "裙子",
    "source_row": 1,
    "target_part": "身体",
    "target_row": 11,
    "reservation_row": 12,
    "start_stitch": 1,
    "end_stitch": 36,
    "loop": "BLO"
  }]
}
```

这个示例表示：身体第 11 圈有 36 针，身体第 12 圈全部挑第 11 圈的前半针钩织，
给裙子留下第 11 圈的 36 个后半针。裙子第 1 圈从该基底圈记号扣对应的第 1 针开始，
按原圈序每个后半针钩 1 短针。身体后续圈继续按原图解完成，再接入裙线。
预留操作圈与接回的基底圈是不同圈；即使预留操作包含增减针，预留数量仍由基底圈决定。

当前生成器只自动安排身体接裙，使用完整一圈的针目，身体与裙子按相同实体序号一一对应。
腰位来自模板安排；优先在筒壁中寻找原计划腰围的圈次，否则按实际基底针数重新生成裙腰。
头身一体采用合并后的身体段圈号，不引用已不存在的独立身体。修改尺寸时重新生成引用。
这不代表已验证腰位、面料走向或实体穿着效果。

校验覆盖部件/圈号存在、预留操作位于基底圈之后、完整范围与起针数相等、
FLO/BLO 操作式、实体数量、与结构连接图一致、重复针目引用以及循环依赖。
编辑或导入矛盾记录会被阻止；打印导出也执行相同门禁，并从当前引用生成装配说明。
表格编辑若改变特殊挑针圈的数字，需同时提供相应的明确操作式。

没有该记录的旧接裙备份仍可读取，但会提示缺少精确接合信息；导入不会偷偷重排旧图解。
CrochetPARADE 导出子集尚不表达这种跨部件接回操作，会跳过接入部件并明确报告部分导出，
不能将剩余部件的语法通过解释为整件连接已验证。

自动回归使用自制图解，见 `tests/test_stitch_attachments.py`、`tests/test_project_backup.py`。
它们验证数据与操作的一致性，不替代真实照片评测或实体试钩。
