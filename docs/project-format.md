## 图解数据的一致性与兼容读取

图解备份顶层版本为 `schema_version="2"`；未标版本和版本 1 的旧备份可继续读取。
旧版应用会拒绝版本 2，避免将不认识的选色字段静默丢弃后重新保存。以下字段均可省略：

| 字段 | 含义与恢复行为 |
| --- | --- |
| `params.parts[].opening_row` | 部件用于装配的开口圈号，必须引用本部件实际圈号。裙腰默认引用首圈；无此字段的旧裙筒也按首圈恢复，帽口与四肢沿用末圈。 |
| `params.head_opening_stitches` | 独立头部留口的可选生成目标，至少 6 针且不超过当前头部最大围。存在时，头部 `opening_row` 必须引用实际末圈，末圈针数须等于目标，且说明不能同时要求收口；缺失时不启用自动留口生成。 |
| `params.parts[].gauge` | 帽子或独立裙筒的可选小样，包含 `stitches_per_10cm`（6–40）与 `rows_per_10cm`（8–50）两个有限数值；不接受额外字段。缺失或为 `null` 时沿用 `params.gauge`，重新保存时省略空字段。 |
| `params.yarn_spec.swatch_gauge` | 称重试片实际测量的密度，结构和数值范围同上。必须与完整克重、每行针数和行数一起提供。缺失时保留旧称重数据，但在确认前不用于实测用量计算；不会在导入时猜测或自动补写来源。 |
| `rounds[].region`、`height_range_cm` | 生成的底盘和筒壁区域，以及沿施工方向的纵向范围（cm）。径向底盘范围为 `[0, 0]`，不占用纵向照片色带；筒壁尺寸和取色使用同一范围。缺失时不猜测或改写旧图解的逐圈颜色。 |
| `rounds[].auto_color_note`、`parts[].auto_color_summary` | 自动换线动作与配色摘要片段；`notes` 仍携带可直接阅读的完整说明，兼容原有导出入口。载入或编辑时根据当前圈色刷新这些片段，保留其他人工文字；旧备份仅迁移可识别的既有自动文案。 |
| `parts[].head_diameter_cm` | 一体头身中保留的头部直径，用于材料清单；不把整件高度或最大身体围度当作头径。旧文件缺失此依据时仍保留原有材料估算回退。 |
| `parts[].color_origin` | `"manual"`：部件基础色由用户显式选择。缺失仅代表来源未记录，可能来自生成或先前手工修改；不记录逐圈来源。 |
| `parts[].instance_colors` | 按份颜色覆盖，长度为 `quantity` 的数组，`null` 表示沿用圈色/部件色。全部为 `null` 时省略；长度不符时拒绝。材料按份统计，导出按份列色。3D 按份取示意色，有实体 ID 时按 ID 对齐；空白槽沿用部件主色。无法解析的自定义名用中性灰，不沿用部件旧色。逐圈条纹仍不画。 |
| `params.display_colors` | 自定义颜色名到屏幕 hex 的可选表，最多 64 条。一个名称对应一个 `#rrggbb`，各部件共用。不是品牌色号。色表名、十六进制本身和 `skin`/`body` 不写入。缺省与空表等价。只改这张表保留已完成圈次。 |
| `parts[].instance_color_ids` | 与颜色数组等长且不重复的实体 ID，用于重排后将颜色绑定到同一实体。新单份选色需要稳定结构 ID；已单独选色的实体须先恢复部件配色才能删除。旧数据只有序数时历史归属无法验证。 |
| `parts[].color_section_mode` | `"head_body"`：一体件使用颈部标记区分头部、身体颜色；尺寸或密度重算时映射分段颜色，无法安全映射时拒绝。 |

这些字段记录生成模型的依据，不代表成品尺寸或配色已通过实物验证。自动摘要变化本身不会
清除整件进度；**只改颜色**（针数、针法、连接与人工文字均未变、实例顺序也未变）时已完成
圈次全部保留，界面会提示已钩出的旧颜色不会因为图解改色而改变。针数、针法或人工文字等
施工变化仍从首个受影响圈起按既有依赖规则清理进度；颜色与其他施工变化同时出现时按后者
处理；跨部件预留半针接合涉及的部件与实例顺序变化也一律沿用保守规则。

单用户历史的持久记录 ID 使用 `history_id`，当前页面控件使用 `result_id`。每次从历史载入
分配新的展示 ID，重新保存仍更新原历史记录。两种 ID 均不写入图解备份、分享或工程文件；
工程进度继续绑定实际部件、实体与圈次。仅调整结构示意位置或旋转时保留原针法，尺寸、
数量或连接变化仍须重新生成并校验。

### 独立头部留口

结果页的局部修正区域提供「独立头部留口」。勾选「保留颈部开口」，输入所需针数，
点击「预览头部留口修改」，核对圈序、完成进度及装配变化后再应用。取消勾选并预览，
可恢复对应塑形风格的闭合模板。头身一体已有连续颈部，不使用独立头部留口。

本功能按当前尺寸、密度和球形/理想球/蛋形模板重算头部，保留冠部及主体段，在收针段
结束到指定针数。允许 16 等非六倍数目标；例如 18→16 使用 `(7X,A)×2`，消耗 18 针、
产出 16 针，不把目标四舍五入为 18。实际末圈记录在 `opening_row`，不会只给中间圈
改个标签而继续钩闭合。此操作会替换头部手改，其他部件仍按构造及实际连接判定保留。

装配说明列出头颈及身体实际开口圈与针数；两侧针数不同时提示核对缝合分配。
Markdown/PDF 同时列出声明开口。开口大小、头颈支撑、缝合位置和成品比例仍需试钩。
模板留口不等同于复刻已知图解；峰值和末圈吻合也不证明圈数或实物形状一致。

目标随备份、工程、历史、分享和试钩原图解保存，后续改尺寸、结构或密度时继续使用。
若新头围小于目标，操作失败并保留当前图解，应先调小留口目标。显式删除头部会移除该
选项；原始试钩字节和身份检查仍保持。手工指定的末圈开口没有生成目标字段时，也可
预览恢复闭合；启用自动留口后按新模板计算。旧文件可继续读取，需要当前或更新版本
才能在重生成时保留这一新选项。备份顶层版本仍为 1。

### 帽子与独立裙筒密度

结果页「局部修正」中展开「🧵 帽子与独立裙筒密度」，选择部件，勾选「使用独立小样密度」，
填写 10cm 针数和行数，点击「预览部件密度修改」，核对后应用。仅支持帽子和独立裙筒；
挑针接裙沿用身体密度。没有独立部件时不显示此入口。取消勾选并预览可恢复默认密度。

例如默认 30 针 × 32 行，帽子设为 26 针 × 28 行，头身与手臂继续使用默认值。
该部件的针围、圈高、色带位置、塑形提示、用量、预览和 Markdown/PDF 共用所设密度。
实际密度变化重算该部件并清理受影响进度；仅显式固定或取消固定相同数值时，保留手改
圈序与进度。以后改变默认密度时，显式设置的数值不随之改变；尺寸和连接变化仍可能
要求重新生成。应用、撤销重做、历史、备份、分享和工程恢复保留此字段。

用线按部件实际密度计算，再按颜色汇总，同色不同密度不会全部套用一个单针克重。
线材规格仍只有一份并适用于所有颜色；实测克重仅覆盖与该试片记录密度相同的
部件，其他密度使用现有面积经验估算。混合时明确显示两种依据，不宣称已测量全部部件。
钩针条目合并相同参考规格，实际针号须依各部件小样核对。

现有试钩记录只保存一组小样。只要任一部件密度不同于默认值，界面禁用「以当前图解新建试钩」，
API/CLI 同样返回明确限制；请先用钩织工程保存进度与备注。显式数值等于默认值时仍可
新建试钩。已有试钩包继续绑定原图解；按实测密度预览只改变默认密度，单独固定的部件
保持设置，原记录不随当前改图重绑定。分部件实测记录需要后续独立的格式设计。

无独立密度的旧工程和试钩包保留原图解修订身份、原始字节校验、进度与备注。
新增字段需要支持本功能的当前或更新版本才能正确编辑和重新生成；旧应用可能忽略它，
不要用旧版本重新保存带独立密度的文件。根备份仍为版本 1，导出缓存为 **14**；
部件字段见 [CrochetPart Schema](schemas/crochet_part.schema.json)。数值一致性不证明实物合身或耗线准确。

### 实测试片克重与来源密度

「按实际毛线与试片估算用量」同时记录称重试片的实际 10cm 针数与行数，写入
`params.yarn_spec.swatch_gauge`。新记录未显式提供来源密度时，以录入当时的默认密度
作为起始值；界面可填写不同的实际密度。以后修改默认密度或部件密度时，已记录的
来源保持原值，计算按部件实际密度与它匹配，而不是与新的默认值匹配。

例如称重记录为 30×32、100 针重 5g，帽子固定 30×32，试钩将默认密度改成 26×28：
帽子继续使用原实测克重，其他 26×28 部件按经验估算。固定为 26×28 的帽子则不能
因为默认值也改成 26×28，就套用那份 30×32 的称重。线标米重比仍适用于所有颜色。

旧记录没有 `swatch_gauge` 时保留克重和针数，显示“旧试片未记录测量密度”；在材料
表单核对并勾选「已核对旧试片的测量密度」后才可使用实测。确认前仍可恢复、保存工程，
但用量改按经验估算。仅改线标不会重绑定已有试片；撤销、重做及工程恢复保留对应来源。

材料表单可点击「预览材料估算修改」，对照克重、米数、购线团数、预留比例、线标及
称重试片来源。预览不替换当前图解，「取消预览」保留原材料；「应用这次修改」使用
点击预览时的方案，同时保留应用时最新的完成进度与工程备注。旧试片仍须先核对确认
来源密度才能预览或更新；取消预览不会给旧记录绑定来源。也可直接「更新材料估算」。

不为旧数据补写来源或空字段。旧工程先核对原始修订绑定，再恢复进度和备注；由于未确认
称重的派生用量改为经验估算，会话规范化结果可与旧材料摘要不同。试钩包保留原图解字节、
SHA 和记录绑定，并继续使用同次规范化导入结果作为会话基线，不能把这一变化误判为用户改图。
这不绕过真实针法、颜色、数量、密度或试片来源变更的身份检查。

线团克重、线团长度和试片克重须为有限数值，且至少为 `0.000001`（单位分别为 g、m、g）；
损耗百分比也须为有限数值。布尔值不作为数值使用，合法数字字符串仍可读取。此下界用于
防止浮点溢出和中间计算下溢为零，不代表称重精度或实际材料可行性；展示值仍会按既有规则舍入。
极少数旧文件若含有低于下界的数值或布尔线材字段，现在会被拒绝；应先用旧版打开并在
材料表单中改为实际数值，再保存新的钩织工程。不要直接编辑工程文件绕过图解修订与进度绑定。
导出缓存升级为 **14**，以便旧会话重新执行校验。

新字段需要当前或更新版本才能正确保留和计算；根备份仍为 1，试钩格式未变。
契约见 [YarnSpec Schema](schemas/yarn_spec.schema.json)。本项只记录一份称重试片来源，
尚未扩展为多组分部件试钩记录，也不代表耗线已经完成实体校准。

### 尺寸编辑与手改保留

快速调整尺寸或编辑结构时，对照同一生成规则下的新旧模板。能确认构造未变的部件，
保留当前逐圈手改、颜色、备注与开口信息。例如手臂手改为 9 圈后，只改变头部直径，
手臂仍为 9 圈；改动的头部重新生成。最终针数、材料、装配及导出按实际保留的内容刷新。

判断包含生成时使用的隐含尺寸、数量、配色、一体件及接裙预留关系；不只比较当前
编辑的尺寸字段。头身一体的头部变化会重算整个合并件；固定裙腰按新身体重新定位，
接裙引用仍须与实际圈序匹配。需要重算的部件会覆盖原逐圈手改。

改变默认密度会重算沿用默认值的部件；独立设置密度且构造未变的部件继续保留手改。
旧结构不能稳定生成对照模板时，仍沿用整份重算。
本功能保留人工编辑内容，仍会计算新旧模板，不代表提升了生成速度或验证了实物适配。
应用前可预览影响；有效完成圈次、个人备注、历史名称及存储绑定继续按既有规则保留，
撤销、重做与工程恢复继续可用。保留部件合入后重新校验，失败不替换当前图解。

提交的规范图解修订与当前内容一致时，不替换展示 ID、不消耗撤销快照，也不清空
重做记录；相同预览的应用会关闭预览并提示内容未变。判断使用完整规范图解修订，
真实针法备注、颜色、数量、密度、线标或试片来源的改变仍会记录为修改，即使汇总
针数或估算克重相同。此规则也适用于逐圈、留口与部件密度等编辑入口。
快速尺寸未变化且结构头径与原分析一致时，保留原尺寸来源，不重算针法。若此前独立
修改结构导致两个头径不同，页面会提示：提交将同步分析头径，可能重算采用隐含尺寸的
部件；可先预览影响。无变化提交不会同时显示“已重新生成”的成功提示。

首次保存历史会建立当前工作会话的存储绑定。撤销、重做和应用保存前准备的预览时，
继承当前 `history_id`，不从旧图解快照恢复或清除该绑定；新建和重新导入仍按新工作处理。

试钩包的原始图解字节及记录 SHA 始终保持原有证据绑定。打开旧包时，以同一次规范化
导入的图解计算会话比较基线，防止新增默认字段或刷新自动说明被误判为人工改图；
用户真正修改针法、圈序、颜色、数量、密度或工艺说明后，仍须重新核对与原试钩的关系。
CLI 的 `parts_source="cli_explicit"` 只记录部件来源，不确认主体、头部或比例，
也不触发完整人工复核标记。

备份中的复核来源是记录值，不是独立认证。结果页只把布尔 `true` 解释为已人工确认；
打印导出只把已知主体范围标记解释为主体已确认，并优先保留“仍需复核”的状态。
字符串、数字、显式 `null` 或未知标记保留原值并提示重新核对，不再自动显示“已确认”；
缺失的旧字段仍按旧记录兼容。头部框必须
具有有效坐标且与头部分段一致，才能显示人工框选来源。
图解和工程格式不变；导出缓存版本为 **15**，旧会话须重新生成 PDF。

### 格式版本与升级

备份文件、分享链接、本机历史、工程文件和试钩包里的图解都经同一条迁移链
（`app/services/migrations.py`）转换为当前格式，再进入校验与重建。没有
`schema_version` 的旧记录先迁移为 `"1"`，再按不猜测颜色来源的版本 1→2 步骤升级；
高于当前、未知或非字符串的版本一律拒绝，不猜测兼容性：导入提示“不支持的图解格式版本”，
分享链接按无效处理，历史记录记录日志后不载入。

以后需要改变已保存格式时，提升 `app.schemas.SCHEMA_VERSION`，并在迁移链中登记一个从上一版本
到新版本的步骤。步骤只处理纯 JSON 数据，不依赖之后可能变化的业务代码；测试会检查每个已登记
版本都能逐步升级到当前版本，并用 `tests/fixtures` 中冻结的旧文件核对升级结果。工程进度绑定的是
文件中原样保存的图解修订，恢复时先按原数据核对修订，再使用升级后的图解。工程状态
（`project_state.schema_version`）与试钩记录各自独立版本化，不经过这条迁移链。

## 保存工程

结果页展开「我的钩织工程」，填写备注，再点击「保存工程（含进度）」。
弹窗中的 JSON 是点击保存时的快照，包含当时每份部件已完成的圈次。继续工作后须再次保存。
关闭页面前将文件下载到自己的设备；从侧栏「打开已有工作」下的「打开备份图解」上传，即可在照片页继续。
结果页自身的导入入口则恢复到所在标签页。

普通「备份完整结果」及分享链接包含图解，仍可能保留照片分析、轮廓与配色摘要；
96px 照片缩略图 `preview` 与画笔修正掩码 `geometry.mask_review` 在导出前剔除
（审核 F-05）。私人备注和进度只进入工程文件。工程文件与新建试钩包同样剔除这两个字段；
恢复旧试钩包时，为保留记录的校验绑定，旧 `pattern.json` 的字节及其已有字段会原样保留。
备份仍保留修正后生成的图解、轮廓摘要与配色，但无法恢复画笔选区或识别画笔修正来源；要重新修正须重新上传
照片。启用单用户历史并选择「存入历史」时，掩码和缩略图会保存在部署主机。
撤销/重做历史仍属于当前会话，不随工程保存。旧版应用可能只读取工程的图解部分，
请用支持工程状态的当前版本恢复进度。

工程保留顶层图解字段（当前 `schema_version="2"`、`analysis`、`structure`、`params` 等），
增加可选的 `project_state`：

```json
{
  "schema_version": "1",
  "pattern_revision": "图解规范序列化后的 64 位 SHA-256 十六进制值",
  "saved_with_version": "保存文件的软件版本",
  "completed_rounds": {
    "[\"手臂\", \"arm_left\", 3]": true,
    "[\"手臂\", \"arm_right\", 1]": true
  },
  "notes": "个人线材、暂停位置或返工备注"
}
```

上例展示 `project_state` 的形状，哈希占位文字不是可导入值。圈次键由部件名、
结构中稳定的实体 ID 和实际圈号组成；旧结构使用 `copy1`、`copy2` 等实体序号。
只有已完成圈次写入 `true`，未完成圈次省略。备注最多 20,000 个字符。
文件上限 20 MiB，粘贴上限 2 MiB；带 BOM 的 UTF-8 文件可读取。

### 名称相似的部件与进度隔离

自定义部件“练习_copy2”和“练习”的第二份实体分别记录完成圈次，保存、恢复和
普通/分页界面保持一致。「全部完成/重置」只作用于所选部件的全部实体；这些操作及
「前往下一未完成圈」保留其他部件的进度和工程备注。编辑后或撤销恢复时，仍按上文
部件名、实体 ID、实际圈号对应完成记录，工程格式和圈次身份无需迁移。

撤销或重做时，施工未受影响的圈保留当前最新的勾选和取消勾选；施工受影响的圈
恢复目标图解的进度快照，不把不同针法的完成状态直接转移。若当前完成圈次无法安全
对应目标图解，界面会显示数量；恢复的进度仍应按实物核对。

当前版本修复了相似名称引起的重复控件、恢复时多勾选及越界状态清理误删问题。
旧文件如已记录了错误的完成圈次，应用无法推断当时的实物进度；请按实物核对、
修正勾选后重新保存。

结构图中的实体 ID 也可能与补出的实体编号相同。例如结构只记载一个 ID 为 `copy2`
的头部，而图解要求两份：新版会为第二份分配不冲突的身份，分别记录进度。编辑结构时，
真实实体按稳定 ID 对应，额外副本按序号对应；两类身份不会互相接管完成状态。

若旧工程恰好把两份实体的完成圈次写成同一个身份，系统无法判断实际完成了哪一份。
导入时先保留当前工作并提示；选择「仅恢复无歧义进度并打开」后，保留其他进度和备注，
有歧义的圈次暂不标记。请对照实物重新勾选并保存新工程；原文件不会被修改。旧会话的
撤销记录遇到同样情况也会提示并暂不标记歧义圈次。

仅存在这类身份冲突的新版工程会在 `project_state` 增加
`progress_identity_version="2"`；旧版因严格校验不会打开带该字段的工程，需用支持此
字段的版本恢复。没有冲突的工程继续使用原有身份与字段，不增加这个标记。

### 导入校验与编辑保留

图解修订值来自 `PatternResult.to_backup()` 的 UTF-8 JSON：键排序、无多余空白、
保留 Unicode 字符、禁止非有限数值，再计算 SHA-256。会话 ID、个人备注和进度不参与哈希。
导入先校验图解、工程版本、哈希绑定及圈次身份，再一次性替换目标图解和进度。
工程被手动改动导致图解与进度版本不符时拒绝导入，保留当前工作；应在应用内修改后重新保存。

可识别的整圈文字也要与操作式一致。例如 `6V，均匀减6针` 的 6→12 数值虽正确，
文字方向仍矛盾，会被拒绝；`加针×5（V×6，每针都加）` 的外层次数也会核对。
“每针都加”和“每2针并1针”须与括号中的 V/A 对应。正确的前导零写法可以使用，
超长文字计数返回简短诊断。只有识别为完整本圈声明的格式才这样检查，
“下一圈均匀加6针”等后续说明和条件句仍需按上下文人工核对。
编辑或导入被拒绝时，当前图解、进度和备注保留；按诊断核对原说明后再应用或导入。

“隔 N 针加/减 1 针”会按实际针序检查相邻加/减针之间的短针数，包括圈尾与圈首。
例如 `(4X,V,V)×6，隔2针加1针` 虽然平均间隔为 2，实际间隔交替为 4 和 0，
因此拒绝；`(X,V,X)×6，隔2针加1针` 的首尾短针接合后间隔为 2，可以使用。
分组、重复组和 FLO/BLO 不改变间隔核对，明确的隐形减针保留工艺身份。
W/M 每次加/减 2 针，不能配写“加/减 1 针”。未附该间隔声明的非均匀或混合塑形
仍按原规则校验；“均匀加/减 N 针”只核对变化数量，不证明实物分布均匀。
旧导出缓存会重新生成，以免沿用升级前对矛盾说明的导出结果。

编辑图解时，仍存在的实体保留首次变化之前的完成圈次，首次变化及之后的圈次重新核对。
比较包含针数、针法说明、颜色和圈序；插入、删除或重排不会把旧进度移到新的针位。
部件整体信息或有效密度变化仍清除整件进度；接合位置或身体改变时，
依赖它的接裙进度也会清除。移动腰位时，身体保留新旧预留操作中最早变化圈之前的进度。
界面报告清除的圈次数，撤销可恢复；个人备注跨修改及撤销保留。
保留勾选只说明前段图解未变化，不能自动判断实物松紧、形态或面料方向是否仍适用。
连接按实体顺序一一配对；重排或改变参与连接的实体时，接入件需重新核对。
预留针目连接的影响会逐层传递；例如外层接中层、中层接内层、内层接基底，修改基底时
三层进度都会清除，与连接记录的排列顺序无关。修改外层不会清除未改动的基底。

长图解分页界面显示所选部件的第一个未完成实体和圈号，点击「前往下一未完成圈」
可跳到对应页；选择逻辑按实体序号、图解圈序查找，并非按最近点击的时间猜测。
跳转不修改勾选状态；全部完成时按钮禁用，重置后可返回第一圈。

部件、逐圈、快速尺寸、高级 JSON 及材料修改均可先预览影响。点击对应预览按钮后，
「局部修正」上方出现变化范围、保留/清除数量，以及总针数、尺寸和材料估算差异。
预览不修改图解；可「应用这次修改」或「取消预览」。方案是点击预览时的快照，
输入或勾选再次改变后应重新预览；应用使用最新勾选。图解被替换后旧预览不能继续应用。
预览与撤销记录只属于当前会话，不写入工程文件。

## 接裙工艺

新生成的挑针接裙图解在 `params.stitch_attachments` 中记录：

```json
{
  "schema_version": "1",
  "connections": [{
    "source_part": "裙子",
    "source_row": 1,
    "target_part": "身体",
    "target_row": 11,
    "reservation_row": 12,
    "start_stitch": 1,
    "end_stitch": 36,
    "loop": "BLO"
  }]
}
```

这个示例表示：身体第 11 圈有 36 针，身体第 12 圈全部挑第 11 圈的前半针钩织，
给裙子留下第 11 圈的 36 个后半针。裙子第 1 圈从该基底圈记号扣对应的第 1 针开始，
按原圈序每个后半针钩 1 短针。身体后续圈继续按原图解完成，再接入裙线。
预留操作圈与接回的基底圈是不同圈；即使预留操作包含增减针，预留数量仍由基底圈决定。

当前生成器只自动安排身体接裙，使用完整一圈的针目，身体与裙子按相同实体序号一一对应。
腰位来自模板安排；优先在筒壁中寻找原计划腰围的圈次，否则按实际基底针数重新生成裙腰。
头身一体采用合并后的身体段圈号，不引用已不存在的独立身体。修改尺寸时重新生成引用。
这不代表已验证腰位、面料走向或实体穿着效果。

### 调整腰位

在「局部修正 → 接裙位置图示与调整」查看三个步骤：基底圈、下一圈 FLO 预留、
裙子第 1 圈 BLO 接回。选择新的实际基底圈可比较拟调整关系，再预览影响并应用。
分件身体只提供筒壁候选；头身一体须有唯一颈部标记，候选使用颈部起的身体段圈号
（包含底部收口，位置需自行核对）。最后一圈不能作为需要下一圈预留的基底。

移动只还原具有生成器标记的原预留说明，并保留其余收尾说明；新预留圈必须是可识别的
普通针法，且不能占用其他连接的针目。新旧腰围针数相同则完整保留裙子针法；不同时
只重算可识别的生成裙腰/过渡圈，保留裙摆针数与按高度映射的配色。手工针法或说明
无法安全重算时拒绝修改，可选择相同针数的腰位或人工调整。所有修改可撤销。

图示可下载 SVG；Markdown/PDF 从当前引用生成相同的接合圈序表。图示不表示实物比例。
图解和工程格式仍保持原版本；导出缓存版本为 7，旧会话中的 PDF 需重新生成。

### 保存腰位偏好

应用新腰位会同时固定它在候选圈序中的相对位置；「预览固定当前腰位」可只固定当前选择，
不改动针法。固定后调整尺寸或重新生成部件，会按原比例选择新候选列表中最近的一圈，
并重新生成实际接合引用和匹配的裙腰。该比例按候选列表顺序计算，不表示厘米高度或实物比例；
头身一体沿颈部至底部方向列出候选，分件身体则沿自身图解的圈序排列。

可选字段 `params.skirt_waist_position` 存在于普通图解备份及工程中，例如：

```json
{"skirt_waist_position": 0.5}
```

数值范围为 0–1，表示候选列表从首圈到末圈的位置；仅有一个候选时，固定操作记录 0.5。
字段只接受有限 JSON 数字，不接受布尔值、文本或空值，且必须同时具有挑针接裙和有效的
精确接合记录。连续调整尺寸保留最初保存的比例，避免逐次取整产生偏移；每次钩织仍以
当前 `stitch_attachments` 的实际圈号为准。新身体没有候选圈时拒绝重生成并保留原图解。
明确移除裙子时一并移除偏好。

「预览取消腰位固定」只移除该偏好，应用后当前针法、接合圈号和完成进度保持不变，
下一次重生成才恢复自动定位。预览会显示腰位策略变化；固定和取消均可撤销。
没有该字段的旧备份继续使用自动定位，图解和工程格式版本仍为 1。
旧应用可以读取当前图解，但其重生成逻辑不会保留新版本的固定腰位偏好。

### 接合校验与兼容性

校验覆盖部件/圈号存在、预留操作位于基底圈之后、完整范围与起针数相等、
FLO/BLO 操作式、实体数量、与结构连接图一致、重复针目引用以及循环依赖。
编辑或导入矛盾记录会被阻止；打印导出也执行相同门禁，并从当前引用生成装配说明。
表格编辑若改变特殊挑针圈的数字，需同时提供相应的明确操作式。

没有该记录的旧接裙备份仍可读取，但会提示缺少精确接合信息；导入不会偷偷重排旧图解。
CrochetPARADE 导出子集尚不表达这种跨部件接回操作，会跳过接入部件并明确报告部分导出，
不能将剩余部件的语法通过解释为整件连接已验证。

自动回归使用自制图解，见 `tests/test_stitch_attachments.py`、`tests/test_project_backup.py`
及 `tests/test_waist_persistence.py`。
它们验证数据与操作的一致性，不替代真实照片评测或实体试钩。

## 手动规划锁针并腿

结果页「局部修正 → 锁针并腿方案（手动核对）」适用于两条腿均留有开口、每个开口针目
各钩一短针、连接锁针两侧也各钩一短针的情况。填写左右腿开口圈号、开口针数、对应圈内
记号针序号及连接锁针数，系统计算 `左腿针数 + 右腿针数 + 2 × 锁针数`。例如左右
开口分别 12、15 针，连接 4 条锁针，则连接圈共 35 针。锁针本身不另算成品针。

记号序号不能超过对应开口针数，结果不能超过系统单圈针数上限。计算只核对输入数字，
并不核实圈号、开口是否存在或针目实际朝向；必须人工确定起点、方向、两侧针位和
首尾连接。如果包含跳针、加减针或其他连接方法，不能使用这个公式。

填完有效方案后，页面展示两侧开口、锁针两侧及总针数的数量示意，可点击
「下载并腿数量示意图 SVG」保存。示意图随当前输入更新，仅表达计数关系；记号只以
数字列出，图形不表示实际针位、钩织方向或部件比例，也不随工程或图解导出。

可下载独立的 `leg-join-plan.json` 保存输入与计算结果供人工核对；下次在同一工具的
「恢复已下载的并腿方案」上传文件或粘贴 JSON，点击「预览恢复并腿方案」查看当前输入
与文件值，再选择「应用恢复方案」或「取消恢复预览」。应用会替换当前工具输入；图解、
部件和进度不变。预览后如修改当前输入、文件或恢复方式，应用会停止并保留输入，须重新
预览。文件限 16 KiB，恢复时校验
版本、完整字段、整数范围、记号以及重新计算的结果；重复字段、损坏或矛盾内容会被拒绝，
当前输入保留。方案文件不绑定具体图解，恢复时不会自动校验图解；须重新核对实际开口、记号及方向。

并腿工具按当前结果保存会话输入。重新生成、成功导入，或应用图解修改、撤销、重做后，
工具会清空输入、恢复预览与部件选择；需要继续使用时，请先下载方案，再在新结果中恢复。
失败的导入或修改保留当前方案；另一标签页的方案和独立试钩记录不受清理影响。

填写完整方案后，可勾选「与当前图解核对圈号和针数」，分别选择左右腿对应部件。
表格比较每侧所填圈号、针数与当前图解；圈不存在、针数不一致，或同一部件不足两份实体
时显示提示。两个选择可以指向同一个具有两份实体的部件，也可以指向两个独立部件。
这个核对不确定所选部件是否为腿，也不能确认实际开口、记号或钩织方向是否正确；
选择仅在当前界面使用，不写入方案文件。部件重排时选择跟随部件名称，所选部件被移除或
改名时清空选择并提示；数量变化后按当前图解重新核对。更换或修改图解后仍须确认选择与实物一致。
若所选圈之后还有圈次，界面提示确认实际在何处停钩以及后续圈、收尾是否需调整；
若该圈说明提及断线、收口或缝合等收尾，也会提示核对具体做法和是否仍有开口。
这些文字提示只是提醒，不自动判断圈口已封闭；即使没有提示，也须人工检查开口和方向。

方案不是图解或工程备份，不能通过这些入口导入，也不随图解、试钩包、打印或 CrochetPARADE
导出。系统尚未自动生成并腿结构或验证实物可钩性。

## 逐针连接核对

在「局部修正 → 逐针连接核对」勾选「显示逐针连接」，再选择部件和圈次。默认不计算
连接图。每个操作列出其来源圈针序、本圈产出针序和挑针范围；SVG 上排为上一圈，
下排为本圈，线段只表达针目来源，不表示线股路径、实物形状、实际朝向或张力。

例如 `FLO(X,V),BLO(A)` 消耗 4 针、产出 4 针：X 用源针 1 产出新针 1，V 用源针 2
产出新针 2–3，A 用源针 3–4 产出新针 4。前两项标注 FLO，最后一项标注 BLO。
W 为一源三针，M 为三源一针；嵌套重复和分置加针保持操作顺序。各圈针序从操作式
起点按 1 编号，不推断实物上的绝对起点，也不自动执行附加文字中的移位或装配动作。

只接受与相邻圈消耗、产出及加减针完全一致的明确操作式。旧图解只有聚合数值时，
显示无法确定针位的原因；不会生成均匀排针作为已知连接。首圈没有本部件的上一圈，
魔法环、锁针起针、跨部件接合和隐形减针的具体挑针过程须通过对应说明另行核对。
预留半针接裙仍使用上文的接裙圈序图。

每页最多 24 个操作，长圈可选择页码；重复组直接跳到所选窗口，不展开全部针目。
「下载本页连接图 SVG」与当前窗口一致。「下载本页连接记录 JSON」包含：

- `schema_version="1"`、`kind="round_stitch_connection_window"` 和
  `basis="explicit_expression"`；这是独立查看记录，不是图解或工程备份。
- 当前部件、来源/目标圈号、两圈总针数、完整规范操作式及全圈 `operation_count`。
- `start` 为从 0 开始的操作偏移；`operations` 中的操作、源针和产出针按 1 编号，
  对应 `index_base=1`。`complete` 仅表示本窗口是否覆盖该圈全部操作，不代表全图解已验证。
- `pattern_revision` 为当前图解的规范化哈希，不包含私人备注或完成进度。

查看、翻页和下载不修改图解或钩织进度。应用图解编辑、导入新结果或撤销/重做后，
查看器恢复未启用状态；可重新启用核对新图解。此功能未运行外部仿真或实体试钩。

### 隐形减针与图示圈号

`inv-sc2tog` 与普通 A/sc2tog 都可按 2→1 计算，但规范操作式保留各自的工艺身份。
例如 `2X,inv-sc2tog` 保留原标记，仍消耗 4 针、产出 3 针；嵌套重复、计数、编辑
和备份均保留它。Markdown 的针法列保留明确操作式；只有文字工艺提示时显示待核对。
PDF 仍打印原说明。`invdec`、中文「隐形减针」及英文提示不会自动变成可执行公式。

当前 DSL 子集、符号条和逐针连接图尚未表达隐形减针的完整工艺。DSL 在该圈停止
该部件的后续翻译，标记部分导出，其他可译部件继续输出；图示提示人工核对。
隐形减针与 FLO/BLO 的组合不能自动改写，接裙预留也会拒绝此类圈并保留当前图解。

图示使用原图解中的实际圈号，包括从中间圈开始或圈号不连续的图解；符号条截断后，
标题沿用当前显示的首个圈号。只有旧数据缺少 `row` 时，才按圈序显示。

## 平面网格工程与修色历史

在「平面像素图案」页生成网格后，点击「下载可编辑工程」保存 JSON。下次使用同一页的
「恢复可编辑网格工程」上传文件并点击「恢复网格工程」。网格工程使用
`format="crochet-photo2pattern-grid"`、`schema_version="1.0"`，保存尺寸、色板、
单格颜色编号和尺寸截断信息，不携带原始照片或会话撤销历史；请使用网格页的恢复入口。
文件上限为 1,000,000 字节，与玩偶图解/钩织工程的备份入口不同。

普通量化和抖动生成的颜色编号均保存为 JSON 整数，可直接恢复继续修色。单格与矩形
工具的行号从成品底部向上、列号从左向右；「撤销修色」「重做修色」各保留最近 5 步的
轻量网格快照。实际修改后会清空旧重做分支；选择区域已经全部是目标颜色时不增加历史、
不清空重做，也不重建输出。成功恢复或重新生成网格后，坐标输入与两侧历史重新开始。

生成、恢复、修色和历史切换先准备完整的 SVG、图例、文字/C2C 指令、Markdown 和
工程 JSON，再更新当前结果。准备失败时显示错误，原网格、两侧历史和当前修色输入
保留，可调整输入或直接重试；成功后下载文件与预览同步。普通页面重绘仍复用缓存。
这些保护针对应用内准备失败，不代替关闭页面前下载工程；会话记录不自动跨设备保存。
