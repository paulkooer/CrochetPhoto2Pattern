# 从成熟图解到复杂作品：推进路线

[English](construction-roadmap.en.md) · [原型说明](dressed-doll-design.md)

目标是生成接近参考作品、做法成立的图解。当前穿衣人偶原型没有达到复杂参考作品的
结构还原要求；补齐部件名称、导出成功、针数相等都不能代替这一目标。
颜色继续后放。先补工序表达与服饰构造，再处理照片识别和自动选择做法。

## 第一关：准确表达已经知道的工序

先从成熟图解中识别“在哪里钩、哪些位置保留、何时换工作边、怎样接回”。
不把不支持的工序自动替换成矩形、圆筒或缝合。

2026-11-16 的 `working-path-v2` 已增加以下通用能力：

- 独立起链或从明确的当前环/根部接续起链；跳过的起立链不计为工作针。
- 部分工作、显式保留针位，以及锁针桥两面分别接入衣身和袖窿。
- 转角位由锁针桥与基底的两个连接处建立，有来源记录，不靠修改总数补出。
- 片钩行注明正反面和方向后，可从对应行端挑针；连续翻面行检查反向工作与行号。
- BLO/FLO 的使用和未用半针有记录，后续引用必须有先前预留证据。
- 接合引拔、正式工作针、翻转链和隐形闭合分开；接缝两侧逐位配对。
- 扣眼明确记录跳过的旧针位与替代锁针，不误计成减针。
- 按工序记录针号和密度，未测肋纹不套用普通短针密度。

程序拒绝越界、重复占位、无预留证据的半针、无来源的行端、漏行和未交代去向的工作位置。
原来的独立数字练习仍保留用于回归：已有边 28 位，衣身后续边 22 位，两侧开口各 9 位；
22 中包含 16 个短针产出与 6 个锁针工作位。这组数字没有服装尺寸含义。

```bash
# 只输出工序输入、明确来源记录和说明；--pdf 需要现有的 pdf 可选依赖
python -m app.working_paths --out-dir eval_outputs/armhole-working-path --pdf

# 读取已人工录入的工序；不会换成默认造型
python -m app.working_paths --plan /path/to/working-path.json \
  --out-dir eval_outputs/manual-recipe --pdf
```

输出 `path-plan.json`、`path-result.json`、`path-explanation.md` 及可选 PDF。
不覆盖已有文件。人工工序的 PDF 从同一份已校验操作生成逐行表格及来源示意，
没有维护另一份手写针数脚本。`working-path-v1` 输入仍可读取；新增工序须用 v2，不能冒充旧版能力。

应用入口：**手动输入 → 人工工序图解（校验与阅读）**。上传工序 JSON，点“校验并载入工序”，
查看审查说明、逐行操作，并下载工序、说明、PDF 和来源记录。上传内容改变后，旧下载停用；
错误输入或 PDF 排版失败不会丢掉上一份记录。输入限 2 MiB，重复键、非有限数和未知格式均拒绝。

此入口是人工工序的校验与阅读，不是照片自动生成，也不会修改旧图解、旧试钩包或原有选型生成器。

**这一关仍未完整通过。** 已记录的控制步骤不证明实际织片方向正确，跨圈外钩、混合针高
与一般的边钩边接还未实现；没有织物仿真、合身、相似度或实体证据。
半针与行端是在有来源时显式引入的工作位置，不宣称枚举整块织物全部未使用线圈。
同一分段的连续翻面行按解析后的原始针位检查来源顺序和正反面交替，保留边别名不能绕过检查。
声明了正反面的行另按朝向检查落针方向：同一面朝向制作者时，沿织物各条边前进的转向相同，
换一面则相反。这适用于普通针和接合引拔，不受分段名称和边的别名影响，覆盖行的工作边、
前襟行端、起链未用的一侧和锁针桥的另一侧；肋纹条逐行回到基底时也按此衔接。
重排的工作边内部，相邻两个行端须在织片同一条侧边，行端与其下方起链之间不得跳位。
续钩的首针须在工作环所在针目或相邻针目；接缝声明朝向后，按此检查工作环所在的一侧。
未建模的仍有：转角、锁针桥与相邻针位之间、肋纹条与基底相接处是否相邻，接缝另一侧的摆放，
以及未声明正反面的旧式分段。另有四种写法目前也会通过：`segment` 行声明了翻面，记录的朝向却不变；
锁针扣眼跳过的针数不与锁针数对照，还可以指向另一条边；一行之内相隔的两段之间不查是否起了锁针，
中间的针位可以用保留或成品边声明注销；同一行里接合引拔之后还有普通针时，工作环记在最后一个
接合引拔上，在真正的末针处收线、暂停或续钩反被拒绝。这四种写法也列在工序阅读页、开衫设计页
和工序导出的检查范围里。
方向规则由几何推出，尚无实物试钩印证。结果单列未钩织而声明留边的针位；
“未说明去向为零”只表示账目闭合，包括人工留边声明，不表示所有位置均已实际钩织。

## 第二关：完成一件有依据的开衫

先完成一件开衫的工艺表达，关键项目包括领肩展开、跳针留袖窿、从袖窿挑袖、
门襟与扣眼、下摆与袖口，以及各部分自己的实测密度。每项必须对应明确步骤和来源位置。
本地已人工录入完整开衫候选：衣身、下摆、三处扣眼门襟、双袖、双袖口及接缝均有工序。
对照中发现的原文行号、重复次数与末端接合引用歧义已单列；候选修改不能冒充原文逐字通过。
另有只覆盖领肩、袖窿分路及单侧袖子首行的小样，避开下摆与门襟的修正争议。
自查发现此前下摆60行的论证把“从当前工作环继续起链”当作消耗一个基底针目，
这一推导不成立。60行及门襟末端目前仅保留为未验证的设计假设，完整候选暂停用于整件试钩。
局部袖窿小样不依赖这两项选择；它仍只是一份待实物检查的人工核对稿。

### 从尺寸设计工序，而非手写全部行数

2026-11-17 新增 `app.models.attached_ribbing`，先覆盖沿边短针/引拔肋纹这一种构造。
输入目标边长、肋纹宽度、这种肋纹自己的针/行密度，可生成整数行数与针宽，再分配每次
回到基底接合1或2位的顺序，最后输出逐行工序。接合引拔不计入下一行针宽。
基底顺序、当前工作环、起链落针面、起链后是否翻面由构造做法明确提供；不从总针数猜测。
例如相同的18个基底位置，在假设6cm长、40行/10cm时生成24行及交替2/1接合；
改成30行/10cm后实际生成18行及每次2位接合。这些是假设输入的工程例子，不是参考照片实测。

尺寸量化前后的差异会保留。缺少肋纹密度时只输出具体缺口；超出每次接合1–2位的做法
范围时停止，不改用衣身密度或压缩行数。生成器保留起链未用侧、未闭合末行和可选首行
前半针，不增加留边注销来取得“零剩余”。袖口接缝方向仍需单独决定。

```bash
# 仅作尺寸设计；缺失密度时只有 design-proposal.json，不生成图解
python -m app.ribbing_design --target target.json --out-dir eval_outputs/ribbing-design

# 将设计接入有明确最终工作边与当前环的工序，生成可重新载入的逐行图解
python -m app.ribbing_design --target target.json --base-plan base-plan.json \
  --method method.json --out-dir eval_outputs/ribbing-path --pdf
```

目标格式为 `RibbingTarget`，做法格式为 `RibbingMethod`；输入区分假设密度和用户提供的小样
密度。用户提供数值不等于助手完成实测。沿边肋纹可独立由CLI调用；下面的组合设计将它与
领肩及门襟连接。照片入口和旧选型生成器尚未自动使用它。

### 领肩、门襟与组合工序的第一版

2026-11-17 继续补入三个模块：`raglan_yoke`、`button_band`、`cardigan_design`。
构造方向参考 [DROPS 的自上而下插肩开衫说明](https://www.garnstudio.com/pattern.php?cid=17&id=12821)：
领肩先展开，再分衣身和袖子。本项目的短针首行、五段配针、加针调度与尺寸搜索是独立的
原型设计选择，不是该图解或 JOLA 的复原，也没有来源对本候选的实物背书。

- 领肩用对称五段，四处分界两侧各加针，总增量为8。按肩深分配加针行；固定领口下若衣身
  与袖围无法在明示的针数调整范围内同时满足，停止生成。衣身目标是展开宽度，不含门襟。
- 分袖后区分腋下桥里山、袖窿另一面、预留针位与两处转角，随后衣身和袖子分别生成。
  这只检查声明的工作位置，仍不证明转角朝向、肩部斜度或实际袖窿合身。
- 门襟按下摆端、第一侧、领口、另一侧和另一端的顺序组织工作边；以明确的 `edge_path`
  转移保留边的引用归属，不重复创建布料。行端每行挑一位、跳过末行与根部留边都是公开
  的设计选择，须实物复核。旧别名不能在转移后再消费同一位置。
- 扣眼位置按门襟行密度量化到奇数返回行；过近、太窄或进入领口的情况停止，并记录另一侧
  纽扣的镜像候选位置。扣眼链数独立输入，不据此推断可容纳的纽扣直径。
- 门襟起链总是翻面，首行以下摆末行的另一面朝向制作者；领口从第一侧前襟到达的一端进入。
  先钩哪一侧前襟由衣身末行决定，所以衣身行数为偶数时整条门襟镜像：接合行在反面，
  扣眼落在正面行起头一侧的前襟；奇数时接合行在正面，扣眼在正面行收尾的一侧。两种都生成，
  图解在下摆、门襟、袖口起头处和审查说明里写明接合行朝哪一面、扣眼在哪一侧前襟。
  穿着者左右是按右手钩织推算的，未经实物确认。袖口沿袖子末圈反向接合，因为末圈以翻面结束。
- 衣身、下摆、门襟、双袖和袖口可组合成可重新载入的工序草稿。两只袖口仍保留首末行
  待接合；衣身与门襟各保留一处根部针。没有自动收掉这些边来冒充整件完成。

默认袖口保持打开供审查。也可显式选择 `blo_to_reserved_flo` 新设计候选：末行从末针反向
工作，与首行预留FLO正向配对，末行挑BLO。此时袖口末行以翻面结束，接缝声明朝向制作者的一面，
“后半针”指当时离制作者较远的那一根。该选择使相应接合步骤明确，不证明它对应原教程
的inner/outer朝向或折叠后的外观。未指定时不会自动采用；所有版本仍需实物核对边缘与合身。

### 用线与收尾控制

后续增量补入显式用线模式 `yarn_tracking`。新设计稿分别声明领口至门襟、袖A和袖B三段
工作线。另起线、当前环断线、暂停、恢复及藏起/结束端都有具体步骤和来源；工作针与
接合事件标注所属线段。断线从当前环抽出线端的一般做法核对了
[PlanetJune 的收线说明](https://www.planetjune.com/blog/amigurumi-help/fastening-off/)。
示例预留15cm尾线是可调整的制作参数，不是用线量估计，也不是来源对本图解的验证。

指定袖口接合版在门襟后、两只袖口接合后分别收线，三段线各有两端藏线步骤。打开袖口的
审查版先用记号扣暂停工作环，只藏已产生的起线端；暂停线仍连接线团，下一袖需要另一
可用线头。恢复后才可接合、断线和藏结束端。新编译检查会拒绝直接跳过工作环另接线、
在错误位置收线、提前藏结束端、重复登记同一线端，以及跨分段遗漏翻面。

本版本统一正面RS分袖再正面挑袖，肩深量化为可用奇数行，并保留实际估算深度。这是本
构造选择，不能据此判断其他正反面安排的图解有错。旧工序仍可读取，但无显式用线记录时
结果标为未跟踪。断线和藏线不改变织物针位总数，留边声明也不能冒充已经收线。

`yarn_accounting` 记录的是图解声明；`all_fasten_off_steps_present` 和
`all_weave_steps_present` 只说明步骤已列出，不是实际执行记录。两处起链根部仍用记号扣
定位并保留作边缘检查，转角、折向及合身仍待实物验证。应用的生成缓存同时绑定参数与
生成器版本，升级后旧稿只保留查看，重新生成后才可下载。

应用入口：**手动输入 → 开衫工艺设计（试验）**。可修改设计尺寸，选择密度未知、假设示例
或手动输入小样数据。选择自己的小样时输入框为空，不把示例数值改名为实测。
设计变化后旧下载停用；可下载设计记录、工序JSON和按需生成的PDF。

```bash
python -m app.cardigan_design --design cardigan-design.json \
  --out-dir eval_outputs/cardigan-design --pdf
```

输入格式为 `cardigan-design-v1`，工序来源标记为 `parametric_design`。
缺少后续密度时保留已生成阶段和具体缺口；不退回默认人偶。密度按假设、教程声明和用户
小样分别标记，均不代表本项目已经完成实测。组合工序仍有袖口接缝、根部边缘、转角、
余量与弹性等待核实，不满足整件试钩准备条件；照片自动选择做法和 G3/G4 均未通过。

交付应包括完整步骤、来源位置对照和未解决项。验收逐项对照已有教程；
不能靠增加“外套”“袖子”等部件名称通过，也不能由漂亮的预览图替代做法检查。

## 第三关：复核及局部试钩

| 证据 | 责任与当前状态 |
|---|---|
| 针位与工作路径检查 | 助手负责；完整开衫候选已表达并检查针位，原文歧义未澄清 |
| 对照教程的技术审查 | 助手先做；应标出同一助手自查，不能冒充独立复核 |
| 熟练钩织者复核 | 当前没有独立复核结果 |
| 实物试钩与试穿 | 当前没有结果；先验证关键部件，条件允许时用现有娃娃试穿开衫 |
| 目标外观判断 | 用户确认设计方向；无需替程序审核针法 |

先证明一件衣物可做、能穿，再投入整件复杂作品。记录所有人工改动，区分原稿成立与
制作者靠经验修正。软件检查不能替代实物证据，也不证明最终成品一定失败。

## 第四关：让照片选择做法

有经过检查的工艺模块后，照片分析输出结构设计：领肩、袖窿、裙装、帽子、发型、鞋和配件，
并区分看得见的特征与推测。照片不能唯一确定隐藏连接、原作针数、针号和密度。

识别模型可帮助选择候选做法；完整图解由明确的工序和参数生成，并经过检查。
遇到没有覆盖的构造，应具体说明缺什么，不能静默降成简单造型。
不以读懂一份已知教程代替证明“从照片得到正确做法”。

## 第五关：换作品验证迁移

当前参考作品及其教程用于开发，不能再作为独立泛化证据。
需要另一份没有参与开发的作品/教程对照，并安排关键部件实物验证。
原有 G3/G4 门槛没有因本路线调整；这份数字演示不计入实体试钩结果。

每轮汇报分清：能表达什么、通过了什么检查、实物证据是什么、哪些关键能力还缺。
