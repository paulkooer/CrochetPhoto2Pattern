# 前端设计审视 · 2026-11-03

[文档索引 / Documentation index](README.md)

对 Streamlit 界面做了一轮"设计主管式"审视：先通读令牌与注入 CSS，再把应用跑起来用真实浏览器看，
最后用 DOM 探测核实每一条视觉判断。结论先行：**「图解纸」概念本身成立**——纸面/墨色/记号扣黄的
三色系统、宋体圈行、指标条、hero 环标都已落地；但有 3 处承载概念的实现在 Streamlit 1.60 上
**静默失效**，1 处核心交互有缺陷，另有 1 处与概念直接冲突的通用模板痕迹。本轮已修复这些，
其余为建议，列在末尾。

## 范围与方法

- 对象：`app/main.py`、`app/ui/*`、`.streamlit/config.toml`、`app/ui/mask_canvas/`。
- 工具：系统 Chrome + 仓库自带 Playwright（`scripts/browser/`），合成输入与
  `scripts/check_browser_workflow.cjs` 同源；1440 px 与 390 px 两个视口；Streamlit 主区域是
  内部滚动容器，整页截图改用 6500 px 高视口。
- 核实方式：对 Tab、Radio、指标、圈行读取 DOM 结构与计算样式；勾选圈次后读取
  `<details open>` 状态；所有截图与探测脚本可按 [浏览器回归](browser-regression.md) 的启动方式重放。

## 已确认并修复

顺带：页脚的 `— ` 连接改为冒号；手动页的成功提示去掉 ✅ 与感叹号；结果页引导句改为描述顺序
（先核对比例与结构，再逐圈勾选，需要时修正并备份），不再与成功提示重复。

## 保持不变、经核实有效

- 字体：标题/圈行/指标走 Charter → 宋体回落，正文与控件走系统黑体；数字等宽内衬。
- 指标条：2 px 墨色上边线、无卡片；alert 为白纸 + 状态色左线。
- hero 环标描线动画与 `prefers-reduced-motion` 降级；打印样式。
- 结果页 1–5 的编号章节：内容确实是顺序（比例 → 结构 → 参数 → 装配 → 修正），编号有信息量。

## 建议及后续处理

1. **侧栏信息架构**：标题"创作设置"下先出现两个"打开…"面板，再是驱动一切尺寸的密度。建议密度上移到最前，
   "打开备份图解 / 打开试钩包"合并为一个"打开已有工作"面板放底部，并减少分隔线造成的大段空白。
2. **第 5 章"局部修正"**：JSON 文本域、6 个折叠面板、三组按钮平铺在一起。建议分两层——常用
   （尺寸 / 部件 / 材料）直接可见，高级（JSON / 结构 JSON）收进一个折叠面板。
3. **颜色名 `skin` / `body`**：来自手动流程的占位色，会出现在"颜色:"与 3D 预览；应在生成层映射为色表名
   （数据层，不在 UI 修）。
4. **进度两按钮**"重置进度 / 全部完成"用 `st.columns(2)` 拉得很开；并排靠左或放到面板标题行更紧凑。
5. **说明段落密度**：照片页 3 段、第 3 章 6 段 `st.caption`，首次使用有价值，之后是噪音；可收进"说明"折叠或用
   控件 help。
6. **结构表的"位置 / 旋转"列**是开发者坐标串，对用户几乎不可读，建议默认只在"查看结构 JSON"里出现。
7. **升级防线（已补齐）**：`check_browser_workflow.cjs` 现检查 Tab 键盘焦点和选中颜色、Radio 选中颜色、
   连续勾选后 `details[open]`、进度与整行高亮，以及 390 px 视口的标题和头栏；同时检查画布 iframe 实际接收的主题。

## 2026-11-03 后续实现：信息架构调整

分支 `fix/frontend-info-architecture`，基于 `main` `fcad19a`。落地上面的建议 1、2、4 与 5 的一部分；
建议 3 只做调查并给出方案，建议 6 仍未处理。

### 侧栏（建议 1）

- 顺序：创作设置（编织密度 → 塑形选项）→ 分隔线 →「打开已有工作」（打开备份图解 → 打开试钩包 →
  我的图解（历史））。密度不再排在两个导入面板之后；分隔线从 3 条减到 1 条，侧栏内 `hr` 的上下边距
  由 1.75rem 收到 1.1rem。
- 两个打开入口保持各自的展开面板，用小标题分组而不是再套一层。实测 Streamlit 1.66.1：嵌套 expander
  在外层折叠或展开时都不抛异常（`AppTest` 探针），但嵌套会让上传控件多一次点击，小标题已经承担分组作用。
- 历史面板的"未启用"分支原先在展开面板内 `return`，整个 `render_sidebar` 随之结束；现在只结束历史面板
  内容，默认部署（历史未启用）下后面的内容照常渲染。新增 AppTest 在历史未启用时验证两个入口都可用，
  并实际打开一份试钩包。

### 第 5 章「局部修正」（建议 2、4）

- 顺序：撤销/重做 → 一行说明 → 快速调整尺寸 → 可视化编辑部件 → 逐圈表格编辑 → 按实际毛线与试片估算用量
  → 专项工具（独立头部留口、帽子与独立裙筒密度、接裙位置、逐针连接核对、锁针并腿方案）→「高级编辑（JSON）」。
- 「编辑 JSON 输出」与原「调整部件结构（高级）」合并进一个默认折叠的「高级编辑（JSON）」；两段编辑器始终
  同时渲染，不用单选切换——Streamlit 会丢弃未渲染控件的状态，切换会让未应用的草稿消失。
- 保留：预览与应用的区分、应用后的进度与备注影响说明、未应用草稿提示（编辑区一处，下载区再提示一次）。
- 常用出口集中到可见的「下载与保存」：备份完整结果、下载 JSON、下载 Markdown、PDF，以及历史命名/分享/
  存入历史/导入结果备份；CrochetPARADE 导出移到其后。下载出口不在任何折叠面板内。
- 进度面板的「重置进度 / 全部完成」、撤销/重做、预览的应用/取消与两个 JSON 编辑器的按钮改用
  `st.container(horizontal=True)` 并排靠左（`st.columns(2)` 会把内容宽度的按钮拉开半个面板）。
- 侧栏两条说明合并为一行；去掉重复的"也可使用下方尺寸滑块或高级 JSON 编辑"。

### 颜色名 `skin` / `body`（建议 3）：只调查，未改动

- 来源：`app/models/crochet_params.py` 为未指定颜色的部件写入占位色 `skin`（头部、手臂、腿部、耳朵）
  或 `body`；它们随图解进入备份、工程、分享与历史。
- 已有处理：`app/models/materials.py` 把 `skin`/`body` 与缺省色归并为"肤色（待选色）/ 主体色（待选色）"
  两行材料，用量按此聚合；`app/ui/preview3d.py` 用 `_PLACEHOLDER_HEX` 给它们固定示意色。
- 仍直接显示原始字符串的位置：结果页部件面板的"颜色: skin"、圈行上的颜色字段（若圈级颜色也是占位值）、
  Markdown/PDF 导出中的颜色字段。
- 建议方案（下一轮单独做）：(1) 在展示层加 `display_color_name()`，把 `skin`/`body` 显示为
  "肤色（待选）/ 主体色（待选）"，用于结果页与 Markdown/PDF；数据层与材料聚合不变，备份、工程、分享
  和历史内容不变，导出文字变化需提升 `EXPORT_CACHE_VERSION` 并同步导出测试与文档；(2) 让用户在
  「逐圈表格编辑」的"毛线颜色"列或部件面板里显式选色表色名替换占位值，走现有预览/应用/撤销。
  不建议在生成层直接改写成具体色表名：那会改变已保存图解的含义与材料统计口径（两条"待选色"变成具体颜色），
  并牵动 `_SKIN_PARTS` 的归并逻辑，需要迁移链版本与材料测试一起改。
